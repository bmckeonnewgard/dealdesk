# Deal Desk — going live on Vercel + Supabase

This folder is the whole app, ready to deploy off the Claude platform so it can have a real public link + password, with real shared data behind it.

## What's in this folder

- `deal-desk.html` — the app itself. Now talks to Supabase (Postgres) instead of Claude's artifact capabilities, and all three maps (the Dashboard's pipeline map, each deal's detail-panel location map, and its IC-memo location map) are now real, pannable/zoomable Leaflet + OpenStreetMap tile maps instead of a flat SVG diagram / Google iframe — see "What changed, honestly" below. It also loads the free SheetJS library from a CDN to read uploaded Excel model files entirely in the browser.
- `api/sample.js` — a small serverless function that proxies the app's AI features (OM extraction, deal screening, AI-drafted fields) to the Anthropic API. It holds your API key server-side so it's never exposed in the browser.
- `api/fetch-listing.js` — a small serverless function that fetches a pasted listing URL (Crexi, LoopNet, etc.) server-side and returns its text, for the "…or paste a listing URL" option next to the New Deal modal's OM upload/paste box.
- `vercel.json` — tells Vercel to serve `deal-desk.html` at your site's root URL.
- `package.json` — minimal project metadata Vercel expects.
- `supabase.sql` — the one-time database setup script (see Step 2).

## Step 1 — Create a free Supabase project

1. Go to [supabase.com](https://supabase.com) and sign up (email + password works fine — no Google account required).
2. Click **New project**, give it a name (e.g. "deal-desk"), generate/save a database password (you won't need it day-to-day — the app never uses it directly), pick a region close to your team, and click **Create new project**. It takes a minute or two to provision.

## Step 2 — Set up the database

1. In the left sidebar, go to the **SQL Editor**, click **New query**.
2. Open `supabase.sql` (in this folder), copy its entire contents, paste into the editor, and click **Run**. This creates the one table the app uses, locks it down with security rules, adds a small helper function, turns on realtime sync, and sets up private file-storage buckets for broker call-log attachments and uploaded deal models. You should see "Success. No rows returned."

**Already deployed before?** If you set this app up before the Brokers CRM's "Markets" and file-attachment features existed, or before deals could have an Excel model uploaded to them, you need to re-run this same `supabase.sql` script once (Step 2 above) to pick up the new storage buckets and their security rules — it's safe to paste in and run again even though you've already run an earlier version; nothing gets duplicated or overwritten. Until you do, adding markets to a broker will work fine, but attaching a file to a call-log entry or uploading a deal's Excel model will show an error.

## Step 3 — Turn on anonymous sign-ins

1. Go to **Authentication > Sign In / Providers** (sidebar).
2. Find **Anonymous Sign-Ins** and toggle it on, then save.
3. This lets the app quietly sign each visitor in behind the scenes — no accounts for your team to manage, and it's what makes Step 2's security rules apply to them. It does **not** replace the app's own password screen; see the comments at the top of `supabase.sql` for the honest tradeoffs. (Supabase's free tier allows up to 30 anonymous sign-ins per hour per IP address by default — plenty for a small internal team, but worth knowing if the app ever seems to be refusing to connect.)

## Step 4 — Get your API keys and fill them in

1. Go to **Project Settings > Data API** (sidebar, gear icon) — you'll see your **Project URL**. Then go to **Project Settings > API Keys** and copy the **anon public** key (not the "service_role" key — that one must never go in this file or anywhere client-side).
2. Open `deal-desk.html`, find the `supabaseConfig` object near the top of the `<script>` section (search for `YOUR_SUPABASE_URL`), and replace both placeholders with your real Project URL and anon key. (Or send them to me in chat and I'll fill them in for you — they're not secret, just identifiers; access is enforced by the security rules from Step 2, not by hiding this object.)

## Step 5 — Get an Anthropic API key (for the AI features)

1. Go to [console.anthropic.com](https://console.anthropic.com), sign in or create an account, and add a small amount of billing credit (the AI screening/extraction features are pay-per-use — typically fractions of a cent per request, but it does require an active billing method, unlike using Claude directly in this chat).
2. Go to **Settings > API Keys**, create a new key, and copy it somewhere safe. You'll paste it into Vercel in Step 7 — never into the HTML file itself.

## Step 6 — Put this folder in a GitHub repo

The easiest way to deploy to Vercel is by connecting a GitHub repo (no command line needed):

1. Go to [github.com](https://github.com) and sign in or create a free account.
2. Click the **+** (top right) > **New repository**. Name it (e.g. `deal-desk`), keep it **Private**, and create it.
3. On the new repo's page, click **uploading an existing file**, then drag in every file from this folder (including the `api` folder — GitHub will preserve the subfolder) and commit.

## Step 7 — Deploy to Vercel

1. Go to [vercel.com](https://vercel.com) and sign up — **"Continue with GitHub"** is simplest, since it'll let Vercel see your new repo directly.
2. Click **Add New... > Project**, find your `deal-desk` repo, and click **Import**. Leave all the build settings as their defaults (Vercel auto-detects a static site + serverless function) and click **Deploy**.
3. Once it finishes, go to the project's **Settings > Environment Variables**. Add:
   - `ANTHROPIC_API_KEY` = the key from Step 5
   - (optional) `ANTHROPIC_MODEL` if you ever want to pin a specific model version
4. Go to **Deployments**, open the latest one, and click **Redeploy** so it picks up the new environment variable.
5. Your app is now live at the `*.vercel.app` URL Vercel gives you (you can also add a custom domain later under **Settings > Domains**).

## A free-tier quirk worth knowing

Supabase's free tier automatically pauses a project after **one week with no database activity** (it resumes on its own the next time someone opens the app — takes roughly 30 seconds, then works normally). Since this is an internal tool your team might not open every single day, don't be alarmed if it's a little slow to connect after a quiet stretch — that's just the project waking back up, not anything broken. If that ever becomes annoying, Supabase's paid tier ($25/mo) removes the auto-pause.

## What changed, honestly

- **Data**: now lives in Supabase (a hosted Postgres database), not Claude's artifact storage or Google/Firebase. Real-time sync across everyone with the link, same as before — pushed instantly rather than polling every few seconds.
- **AI features**: unchanged from your perspective, but now billed to your own Anthropic account per request instead of being included.
- **Password gate**: unchanged — still a client-side convenience, not real security. The Supabase security rules (Row Level Security) add a real backstop against random bots, but anyone who can read the deployed page's source could still technically sign in and hit the database directly. That's an acceptable tradeoff for an internal team tool behind a link you're not publishing widely; worth revisiting if that ever changes.
- **Maps**: both maps now use free OpenStreetMap tiles via Leaflet (no API key, no billing account) instead of a hand-drawn flat diagram and a Google Maps iframe — this only became possible once the app left Claude's sandbox, which couldn't reach a live tile or geocoding host. The Dashboard's pipeline map still uses the same built-in state/city coordinate lookups as before (nothing external to fail there). Each IC memo's location map now geocodes that deal's address on the fly via OpenStreetMap's free Nominatim service the first time you open that memo in a session — if geocoding fails (an incomplete or unusual address) it falls back to the same address-and-link you had before, so nothing is ever silently missing. Both maps stay hidden from printed/exported PDFs (same as before), showing the address and a "Open in Google Maps" link there instead — printing a live, tile-based map reliably is a rabbit hole better left alone for now.
- **Tasks board**: now has a 5th column, **Process Improvements**, alongside Doing / To Do / Backlog / Complete — for tracking process-improvement ideas separately from deal-specific work.
- **Screening/OM extraction**: the Screen tab and New Deal modal's OM box now also accept a listing URL (next to the file upload) — paste a Crexi/LoopNet/brokerage link and click Fetch to pull its text in automatically. This is best-effort: some sites block automated requests or render their listing details with JavaScript, in which case you'll get a specific message telling you so — fall back to downloading the page/PDF and uploading or pasting it, same as before. If any AI request (screening, OM extraction, or a URL fetch) fails, the status line now shows the actual reason instead of a generic "try again" message — handy if something needs troubleshooting.
- **Brokers CRM**: each broker can now be tagged with one or more **Markets** they work in (type one and press Enter — shows as a removable pill), and search now matches on markets too. Each entry in a broker's call/activity log can also have real files attached (a forwarded email saved as PDF, a screenshot, a notes file) — click "Attach file(s)" on a log entry, and click an attached file's name later to reopen it. Files are stored in Supabase Storage (a private bucket, not public), and the app requests a short-lived link each time you open one rather than exposing a permanent URL. See the "Already deployed before?" note under Step 2 if you set this app up before this feature existed. Supabase's free tier caps total storage at 1GB and 50MB per individual file — plenty for call notes and screenshots, but worth knowing if someone tries to attach something large. The Brokers list itself is now a stacked list grouped by rating (Hot/Warm/Cold/Not rated), the same visual language as the Acquisitions pipeline, instead of a card grid.
- **Deal location map**: each deal's detail panel (Overview tab) now shows a real, pannable map near the top, geocoded from its address the same way the IC memo's map already worked — no setup needed beyond what Step 2 already sets up.
- **Excel model upload + AI summary**: on a deal's Back-of-Envelope tab, toggling to "Full model built out" now lets you upload the actual Excel underwriting model (`.xlsx`/`.xls`, up to 50MB) instead of only typing in headline numbers by hand. The app reads the workbook in your browser (no server ever sees the raw file) and asks the AI to pull out a plain-language summary and headline figures (IRR, equity multiple, yield on cost, etc. — whatever the workbook actually contains), so anyone can get the gist without opening Excel. You can still link the model on OneDrive/SharePoint too (same "Project folder URL" field as before) — upload and link aren't mutually exclusive. Click "Regenerate summary" any time to re-run the AI read without re-uploading, or the ✕ on the file chip to remove it. This needs the new `deal-files` Storage bucket — see the "Already deployed before?" note under Step 2.
- **Dashboard layout**: the "By stage" breakdown and pipeline map now show right at the top of the Dashboard (just under the filter bar), instead of further down the page.
- **Pipeline map drill-down**: clicking a dot on the Dashboard's pipeline map used to jump you straight to the Acquisitions board, filtered to that state — a little jarring if you just wanted to glance at what's there. Now it opens a popup right at that dot listing the actual deals (name, stage, price, lead), and clicking one opens that deal's detail panel directly, without leaving the Dashboard. The old filtered-board jump is still there — it's just a "View all N in pipeline →" link at the bottom of the popup now, so it only happens when you actually want it.
- **Map scrolling**: a plain scroll over any map (the pipeline map, a deal's location map, an IC memo's map) scrolls the page, same as scrolling over anything else — it never used to zoom the map at all. Now holding Ctrl (Cmd on Mac) while scrolling zooms that map instead, the same convention Google Maps embeds use; scrolling over a map without that held gets a brief on-map reminder of the shortcut instead of silently doing nothing, so it's discoverable the first time.
- **Map z-index bug fix**: opening a deal's detail panel while the Dashboard's pipeline map was visible behind it used to let the map render on top of the panel instead of behind it (a CSS stacking issue in how Leaflet's own map layers interact with the rest of the page). Fixed — maps now always stay behind whatever's opened on top of them.
- **Screening scores**: the Screen tab's result now shows a per-criterion breakdown (with the AI's rating and note for each of your product line's screening criteria) and an aggregate quality score, instead of just a pursue/watch/pass recommendation with no visibility into how it got there.
- **Market and acreage at a glance**: the Acquisitions Pipeline's Compact view now shows each deal's market (parsed from its address, falling back to just the state, or "—") and a combined "4.5 ac · $1M/ac" column, so you can see where a project is and its basis without opening it. The Detailed view picked up the same two fields as highlight cards.
- **Acquisitions count excludes dead deals**: the "Acquisitions" number in the left nav now only counts deals still actively in the pipeline — a deal in the Dead / Passed stage no longer inflates that total. (The full deal count, including dead ones, is still there in the underlying data — nothing was deleted.)
- **Contract document upload + auto-fill**: a deal's Overview tab now has a "Contract documents" section (between Critical Dates and Deposits) where you can upload a PSA, LOI, or amendment (`.pdf`, `.txt`, or `.md`, up to 50MB — `.doc`/`.docx` isn't supported yet). The AI reads it and proposes updates to the fields it actually finds stated — purchase price, PSA status, effective/closing/inspection dates, deposits (including any extra ones like an extension deposit), and a plain-language note covering the seller, escrow/title company, and commission split. Nothing is written to the deal automatically: you get a review list first, showing the current value struck through next to the proposed one, with everything checked by default — uncheck anything you don't want and click "Apply selected" (or "Dismiss" to discard the read entirely). Uploading a later amendment runs the same read against the deal's current values, so only what that document actually changes shows up — nothing to flag manually. Each uploaded document stays listed with its file, an AI-guessed type (PSA/LOI/Amendment) and one-line summary, and whether/what was applied from it; "Re-run extraction" re-reads an already-uploaded file without re-uploading it, and the ✕ removes it (the file only — anything already applied to the deal stays). This uses the same `deal-files` Storage bucket as the Excel model upload, so nothing new to set up if that's already working.
- **Site conditions & overlay maps**: a new section on a deal's Overview tab (Zoning & Site, right above Demographics) for flood, wetlands, soils, environmental, and opportunity-zone screening. Since the app still can't query FEMA/USFWS/NRCS/EPA live, each layer is a one-click deep link to that layer's own authoritative viewer (FEMA flood map, the NFHL viewer, the NWI wetlands mapper, Web Soil Survey, EPA NEPAssist, the CDFI opportunity-zone map) pre-filled from the deal's address and, where you've entered them, its latitude/longitude — you record what the viewer says. A "Layers checked" table stamps every entry with the source's own effective/published date and who checked it when, and a layer nobody's checked yet prints plainly as "Not checked" in the memo rather than silently vanishing — screening isn't determination, so the panel is explicit that NWI isn't a wetlands delineation and the NFHL isn't an elevation certificate. The same live preview and the printed IC memo share one renderer, so they can't drift apart.
- **Resizable deal detail panel**: a deal's detail panel is noticeably wider by default now, and you can drag the thin handle on its left edge to make it wider or narrower to taste (double-click the handle to reset it). The width you leave it at is remembered per browser, the same way the pipeline's Compact/Detailed view choice already was.
- **Taller location map**: the location map near the top of a deal's detail panel was a cramped 200px-tall strip that looked worse once the panel itself got wider — it's now 340px tall so it reads as an actual map instead of a thin ribbon.
- **Passed deals & hit rate**: a new section at the very bottom of the Dashboard (past "Activity") shows how many deals have been marked Dead/Passed, how many have actually signed or closed, and the resulting hit rate — signed/closed as a share of all *decided* deals (passed + signed/closed; deals still in progress aren't counted either way since their outcome isn't known yet, same logic as the "Deal quality" card above it). Under those numbers is the actual list of passed deals, most recent first, each with the date it was marked Dead/Passed (pulled from the same activity log the "What changed" and project-timeline sections already use) — click one to open it. A deal from before activity logging existed falls back to its last-updated date, or shows "—" if even that's missing, rather than being left out.
- **Screen to Close — gate log**: a new section on a deal's Overview tab (between the Go/No-Go decision and the due-diligence checklist) for recording the six decision checkpoints of your acquisition process — Screen, LOI authorization, Investment Committee, Capital, Go-hard, and Funding authorization — each with the answer options that gate actually uses (e.g. Investment Committee is Go / Go subject to conditions / Hold / No-Go; Go-hard is Go hard / Go hard after re-trade / Extend at stated cost / Terminate inside DD). Pick a gate, log who decided, when, and — for a Pass/No-Go/Terminate answer — a reason code (price, market, zoning, site, capital, seller, timing), plus an optional note. Each gate shows its latest decision as a status pill; deciding a gate again (say, after a re-trade) keeps the earlier decision available under an "N earlier decisions" toggle instead of overwriting it. This is a record-keeping layer only — logging a decision here never changes the deal's pipeline stage on its own, so the stage dropdown still works exactly as it did.
- **Due diligence — the work that produces it**: a second checklist alongside the existing 52-item document checklist, unlocked once a deal reaches In Due Diligence. Where the first checklist tracks the standard documents you collect, this one tracks the underlying work that produces them, in six categories: Title & survey, Environmental & physical, Entitlement & zoning, Design & cost, Financial & legal, and Capital raised as its own parallel lane (debt sourcing, lender site visits, equity package, LP commitments, sources & uses) — 33 items in total. It has its own status/target-date/notes fields per item and its own progress bar, tracked completely separately from the original checklist's percentage so the two never mix.
- **Pipeline row column widths (Compact view)**: rebalanced so the Project column (name + address) gets meaningfully more room, at the expense of the Responsible, Updated, and Stage columns, which needed less than they were getting. Market, Price, Acres · $/ac, $/Unit, and Progress are unchanged.
- **Pipeline stages split to match your Screen to Close flow chart**: the old "Signed PSA/DD" stage conflated two very different things — the PSA itself (drafting/negotiating/executing, usually 2-4 weeks) and the 60-120 day due-diligence investigation that follows it, where your G4 Capital and G5 Go-hard decisions actually happen. That's now two stages: **Signed PSA** (the brief pre-execution window) and **In Due Diligence**. Likewise, "Onboarded" conflated closing prep, the close itself, and the 30-day post-close handoff into one bucket that hid any open closing to-dos — there's now a **Closing** stage between Signed PSA/In Due Diligence and Onboarded. The pipeline is 9 stages now instead of 7. Every deal that was sitting in the old "Signed PSA/DD" bucket moves to **In Due Diligence** automatically the first time the app loads after this update (not the new, narrower Signed PSA stage) — that stage could only be entered once your Investment Committee had already approved the deal, so every deal there already had an executed PSA. Deals in "Onboarded" are unaffected. This migration is automatic, one-time, and touches only the `stage` field — nothing else about any deal changes. The DD checklists (both the document one and the "work that produces it" one) now unlock at In Due Diligence instead of the old combined stage. One small behavior change beyond renaming: the "this deal doesn't have a recorded Go decision" confirmation prompt, which used to only fire when moving a deal to Onboarded, now also fires when moving a deal to Signed PSA — matching where the flow chart actually places the IC gate (G3, before the PSA gets signed, not just before onboarding).
- **Contract documents moved up, plus a "Quick update" box**: "Contract documents" now sits right below the location map near the top of a deal's Overview tab, instead of down between Critical Dates and Deposits — easier to find without scrolling. Right above it is a new "Quick update" box: type a plain-language note about what changed (e.g. "we signed the amendment, $100k deposit due tomorrow, closing pushed to December 15") and click "Apply update" to run it through the same AI reader an uploaded document already uses — you get the same review panel (current value struck through next to the proposed one) before anything is written. This is the same feature as uploading a document, just for something you'd otherwise have to type into a note and remember to go update by hand; it doesn't add anything to the Contract documents list since there's no file behind it.
- **Scanned documents now OCR'd automatically**: uploading a PSA/LOI/amendment that's a scanned or faxed image (no selectable text — this is what was behind the "couldn't find readable text, it may be a scanned image" message) now runs it through in-browser OCR (Tesseract) before giving up, the same way pasting an OM/listing PDF into the Screen tab or New Deal modal does. This adds a delay (up to roughly a minute for a longer scan, since it's reading each page as an image) and is best-effort — a genuinely low-quality, skewed, or handwritten scan can still come back with nothing, in which case you'll still get a clear message telling you to key it in by hand. Nothing about a normal, digitally-produced PDF changes; this only kicks in when the normal text layer comes back empty.
- **Word document (.docx) upload support**: Contract documents now accepts `.docx` files alongside `.pdf`/`.txt`/`.md`, reading the text directly in your browser (no server ever sees the file) the same way the other formats already do. Legacy binary `.doc` files (the pre-2007 Word format) still aren't supported — Word, Google Docs, and most other editors can re-save one as `.docx` in a couple of clicks if you run into this.
- **Critical dates and Deposits moved up, plus a 1st deposit date field**: "Critical dates" and "Deposits" now sit right after "Deal overview," near the top of the Overview tab (alongside Quick update and Contract documents), instead of further down past Demographics/Market context/Deal history. The Deposits section also has a "1st deposit date" field now, next to its amount and status, matching the 2nd deposit row — it's the exact same underlying field as "Earnest money date" under Critical dates (that field already existed, just wasn't shown in Deposits), so editing either one updates the other immediately, and a Quick update or uploaded document that reports a 1st deposit date updates both the same way.
- **Fix: "Model did not return valid JSON" on some contract documents / Quick updates**: this is a fix to `api/sample.js` (and, this time, `package.json` too) — not `deal-desk.html`. That's the one exception to "just push the HTML file" (see "Ongoing changes" above): redeploying this update means pushing all three files. The AI-reading step behind Contract documents, OM extraction, deal screening, and Quick update all share one server endpoint with a cap on how long the model's reply is allowed to be; that cap (1200 tokens, originally) was occasionally too tight for a rich read — a dozen-plus fields plus a notes field and an array — so the reply got cut off mid-object and failed to parse. This mostly stayed hidden because a scanned PDF used to fail earlier, at "couldn't find readable text," before ever reaching this step — the OCR fix above unblocked those documents, which is what surfaced this separate, pre-existing bug for the first time. First pass raised the cap to 2500 tokens and trimmed stray commentary around the JSON, which fixed some cases but not all — a detailed real-world Quick update (multiple parcels, an addendum reciting a date in quotes) still failed, for a second, more specific reason: the model was echoing a quoted phrase from the source text (e.g. an addendum "dated as of August 26, 2026") straight into its own JSON string without escaping the inner quotes, which breaks JSON syntax even when nothing is truncated. Fixed properly now with two changes: the cap is raised again to 4096 tokens (still free unless a reply needs the room), and the reply-cleanup step now runs a small, well-established JSON-repair library (`jsonrepair`) as a fallback whenever the first parse attempt fails — it fixes exactly this class of issue (stray unescaped quotes, a truncated/unterminated object, and a few other common slip-ups a model can make), so a mostly-valid reply gets recovered instead of forcing you to fill everything in by hand. This is also the reason `package.json` needs to go up this time — it now lists `jsonrepair` as a dependency, which Vercel installs automatically on your next deploy; nothing for you to run by hand.
- **Market now rolls up to the metro, not the literal submarket city**: the Market shown on a pipeline row, a deal's IC memo, and the passed-deals summary is parsed from the deal's address — but an address that reads "...North Miami, FL..." or "...Sugar Land, TX..." was showing exactly that, splitting off what's really one market (Miami, Houston) into a separate-looking one just because of which municipality the address happens to name. Fixed with a small, explicit lookup table that rolls a handful of known submarkets up to the metro name your team actually talks about deals by: Miami-Dade cities (North Miami, Miami Beach, Hialeah, Doral, Aventura, Coral Gables, and others) → Miami, FL; Las Vegas valley cities (Henderson, North Las Vegas, Paradise, Spring Valley, Summerlin South) → Las Vegas, NV; Greater Houston cities (Sugar Land, Katy, The Woodlands, Pearland, Missouri City, Spring, Pasadena, Baytown) → Houston, TX; NYC boroughs (Brooklyn, Queens, Bronx, Staten Island, Manhattan) → New York, NY. This is deliberately a short, visible list rather than an automatic "snap to the nearest big city" system — that kind of distance-based guess would make a lot of silent judgment calls across the whole country (how big a radius, whether Fort Worth folds into Dallas, etc.). If another submarket shows up that should roll up to a metro, send me the address and I'll add it. Nothing else about the address or the deal itself changes — this only affects the Market label.
- **Dark mode removed**: the light/dark/system toggle button that used to sit in the top bar is gone, and the app now always renders its light color palette, regardless of your OS or browser's dark-mode setting. This was a deliberate simplification, not a bug fix — one consistent look for the whole team, no half-finished dark theme to keep in sync as the app grows.
- **Deal card simplified**: at your request, a deal's detail panel now focuses on the basics instead of trying to hold everything. Removed entirely from the card (and from the printed IC memo): Demographics, Market context (employers, traffic, land/comps, competitive supply pipeline), Deal history / prior IC touches, and Responsible party by stage. Nothing about old deals' data was deleted — if any of that was ever filled in, it's just no longer shown or printed. New at the top of the card: a "Deal basics" section with Lot size, Purchase price, Targeted units, and Developable SF always visible, with price-per-acre/price-per-unit calculated live. The Investment Criteria list is no longer shown inline — instead the card shows a single Quality score with a "View full scorecard →" link that opens the same editable per-criterion ratings in a modal (the Go/No-Go decision itself stays on the main card, since it gates moving a deal's stage). The Back-of-Envelope tab and its "Full model built out" toggle are gone as a separate tab — everything that was there (the toggle, underwriting inputs, capital stack, Excel upload/AI summary) is now behind one "Financial model & underwriting →" link on the main card, opening in a modal. The **Screen tab is removed entirely** — it wasn't working well as a second, parallel scoring flow alongside the Criteria tab; use the New Deal modal's OM/listing-URL extraction to pull details when adding a deal, and the Criteria tab or a deal's own scorecard modal for scoring. The Pipeline board's own "Responsible" column (assigning an owner per stage from the board itself) is untouched — this change only affected the deal card.
- **Pipeline stage colors redesigned to show progress**: the 7 working stages (Prospecting through Closing) used to cycle through a handful of unrelated colors (gray, navy, teal, gold, navy again, gold again, teal again) that didn't correspond to anything — a deal moving forward could get lighter, darker, or just a completely different color for no visible reason. They're now one color (a teal matching the app's own brand accent) that steadily gets darker from Prospecting to Closing, so the color itself reads as "how far along" a deal is at a glance, the same way a progress bar would. Onboarded (green) and Dead/Passed (red) intentionally stay off that ramp and keep their own fixed colors — they're outcomes, not "further along than Closing," so they keep meaning success/failure rather than just being the darkest step. The exact shades were chosen and machine-checked (not eyeballed) for readable contrast and visibly distinct steps.
